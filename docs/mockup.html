Decided so far

  • A repo's sections are numbered boxes, like lazygit's panels: [1] Pull requests [2] Issues [3] Actions [4] Renovate [5] Releases.
  • When you're on a repo, those boxes are the preview on the right. Press l and they move to the left column, with the details of the selected item on the right.
  • l from a box moves focus into the details pane. It doesn't open a third set of columns.

Navigation model

FocusLeftRightKeys
ReposRepo list (★ Renovate pinned, the rest by activity)The selected repo's boxes, as a previewj/k pick a repo · l or 1–5 go in
BoxesThe repo's boxes; the focused one growsDetails of the selected itemj/k within a box · 1–5 / tab between boxes · l into the details
DetailsSame boxes, dimmedDetails, focused, with tabsj/k scroll · [ ] tabs · actions

h always steps back one level. The action keys (m, a, x and so on) work from both the boxes and the details pane.

Where Renovate fits

  • ★ Renovate uses the same boxes, but they span every repo: [1] Renovate PRs [2] Updates by dependency [3] Dashboards [4] Failing CI.
  • [2] Updates by dependency lists each update once, e.g. postgres 16.4 → 17.0 ×2. Pressing m on it merges that update in every repo.
  • In a regular repo, [4] Renovate holds the Dependency Dashboard entries. space ticks an entry, which asks Renovate to create that PR now.
  • space marks PRs in any PR box, and m merges everything marked. The confirm dialog warns about failing CI.

Keymap

Stack: a recommendation

I'd go with Go + Bubble Tea + Lip Gloss:

  • Lip Gloss handles bordered boxes with titles on the border, and layout like this, with little effort.
  • Gitea and Forgejo both have Go SDKs, and the tea CLI is written in Go, so reusing its config is easy.
  • It builds to a single static binary, so installing on homelab boxes is trivial.

Rust + ratatui is just as capable, and it's the better pick if you'd rather write Rust. Yazi's source is a good reference for the column handling.

Open questions

  • When j reaches the bottom of a box, should it stop (like lazygit) or carry on into the next box?
  • Should the focused box grow, as in the mockup, or should every box keep a fixed size?
  • Are these the right boxes? Possible additions: Branches, Milestones, Packages.
  • Should per-repo [4] Renovate show the dashboard entries, as mocked, or Renovate's PRs split out of [1]?
  • Forgejo Actions API: does your version expose job logs and re-runs?
  • One Forgejo instance or several? Should refresh be manual, polled, or both?
